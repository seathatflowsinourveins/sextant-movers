## Evidence and learning

- Each tunable value has a registry row and source. A sourced value without calibration is an uncalibrated starting value, never measured success. If the value or its authority is missing, keep it unavailable; fixtures supply no default authority. Reviewed changes occur between sessions, and nightly tuning only proposes. [ADR-0018](../adr/0018-evidence-and-learning-loop.md)
- One cumulative trial ledger, tiers never pooled, history never reset, rejected variants kept. [ADR-0018](../adr/0018-evidence-and-learning-loop.md)
- Nightly reflection and tuning write proposals only; a label or a one-day anecdote never adopts a change. A nightly proposal PR carries no registry patch and never calls the registry's reviewed-write path; adoption is a separate change in the consuming runtime. Manual Orca runs skip the scheduler's precheck, so readiness is checked at run entry too. [ADR-0018](../adr/0018-evidence-and-learning-loop.md), [L4 design](../research/2026-11-06-nightly-proposals.md) ([#143](https://github.com/seathatflowsinourveins/sextant-archive/pull/143))
- Read outcomes only as of the cutoff; keep superseded and negative lessons. [ADR-0018](../adr/0018-evidence-and-learning-loop.md)

## Harness

- One manifest row per pick or practice, with pin, application and `just prove` command; nothing enters without one and a stopped practice is deleted. When merging parallel lane work, retain main's rows and append the lane's new rows at the end of their existing section. Reusing a pin that main already carries is not a new pick. Only a new pick waits `pins.json`'s `release_cooldown_days` (lead ruling 2026-11-09). [ADR-0001](../adr/0001-sextant-foundation.md); lead direction for [PR #70](https://github.com/seathatflowsinourveins/sextant-archive/pull/70), 2026-11-06; [merge lesson](retrieval.md)
- A PR lands through squash auto-merge only when ci, source and review pass. `ci` runs on `pull_request` on GitHub-hosted runners with no secrets. One `workflow_run` gate from the default branch then posts `source` (Danger, API-only) and `review` (dsh through PerryLink/dsh-github; the API-key reviewers run only for a dsh-authored PR, a risk-path PR, or a gate-path PR, which gets one extra second-family review in place of an owner label, by the owner's 2026-11-09 decision; a Codex author adds one only when it selects Claude (D-34, 2026-11-10)). So a PR cannot change its own checks. Review to Google's standard: approve a PR that definitely improves code health even if it isn't perfect, and let facts and data overrule opinion. A finding blocks only as an Always-P0 item, or as a hard-line, custody, money or correctness defect with a failing witness at the exact head. Everything else goes to one follow-up issue per PR. Keep one concern per PR. At most two reviewed commits: if a blocking class recurs, split the PR or ship that path disabled and failing closed, and when a bug class recurs, simplify the design instead of patching instances. A branch-only `just ci` pass does not validate CI's merged tree: retain both branches' registered proofs when resolving conflicts, then test the combined tree. Before turning auto-merge on, check the size budgets on current `main` plus the PR, because a green ci on a stale `refs/pull/N/merge` can still break `main`. [ADR-0001](../adr/0001-sextant-foundation.md); [Google eng-practices](https://github.com/google/eng-practices/blob/3bb3ec25b3b0199f4940b1aa75f0ac5c5753301c/review/reviewer/standard.md) `standard.md:31-32,72,90`, `small-cls.md`, `looking-for.md:46-57`; [Release Toggles](https://martinfowler.com/articles/feature-toggles.html), read 2026-11-09 ([#101](https://github.com/seathatflowsinourveins/sextant-archive/pull/101), [#164](https://github.com/seathatflowsinourveins/sextant-archive/pull/164))
- Converge, don't collide: a setup step edits its target in place rather than skipping once it exists ([#55](https://github.com/seathatflowsinourveins/sextant-archive/pull/55)); configure by directory and marker, never a shared list that every lane appends to ([#92](https://github.com/seathatflowsinourveins/sextant-archive/pull/92)); a memory floor reads MemAvailable, not "free"; write a post body with a quoted heredoc (`<<'EOF'`) and a `__STAMP__` that sed fills from `TZ=America/New_York date`, because an unquoted heredoc runs backticked text; grep a regex-form deny rule by its pattern, not a literal word; and one shared GitHub token is one budget, so no polling loops, and GraphQL reads first ([issue #44](https://github.com/seathatflowsinourveins/sextant-archive/issues/44)).
- Keep always-loaded rules short and enforce boundaries instead of hooks; the only hooks are the secret scan and the skills runtime. [ADR-0001](../adr/0001-sextant-foundation.md)
- Agent sessions run locally. Checks run on GitHub-hosted runners, which are free on public repos. PR code runs only in `ci`, with a read-only token and no secrets, and fork PRs need approval and get no secrets. [ADR-0001](../adr/0001-sextant-foundation.md)
- Run harness proof subprocesses with explicit fixture environments; inherited Bash functions or startup files must not replace fake tools with the running service. [AO proof isolation](../research/2026-11-06-agent-orchestrator.md#offline-proof-isolation)
- Declaring a plugin is not installing it: the committed `.claude/settings.json` turns a plugin on, but an untracked `.claude/settings.local.json` or user settings must enable it before Claude Code fetches it ([loading.md](https://code.claude.com/docs/en/plugins/loading.md), read 2026-11-11). So `scripts/plugin_shelf.py` installs at scope `local` from the main checkout, as the origin repository's `deploy/wsl/shelf.sh` does, and session start checks the vendor's own install records.
- A step that drives a vendor CLI is proven by one real run in an isolated config directory (`CLAUDE_CONFIG_DIR` for Claude Code) before it merges; a stub proves only our argument list. The shelf install step merged on a stub alone and failed on its first real install.
- GitHub's merge does not apply this repository's `merge=union` rule for `docs/manifest.md`, and the local union driver keeps both forms of a row that one side edited. Measured on this repository's PRs #47 to #66: inserts at distinct positions merge; an edit beside an insert, two inserts at one position and edits of two neighbouring rows conflict on GitHub. PR #66's first head was `CONFLICTING` there, while the local merge of the same two commits finished without a conflict and left four rows for two. So land row-editing PRs one after another, and after every local merge or rebase that touches the manifest compare it with the default branch's: `diff <(git show origin/main:docs/manifest.md) docs/manifest.md`. git's own text for the driver says "the user should verify the result" (git/git@v2.56.0 `a018953688f1b10bddf91bff8747068f5f4746a4`:`Documentation/gitattributes.adoc:1125-1132`). `tests/proofs/test_manifest_union.py` refuses a repeated row title, and a renamed row's old title once it is in that file's `RETIRED` list, so add the old title there in the PR that renames a row and run the file after the merge; PR #66 renamed a row without it, and the local merge kept the old twin unseen.
- Update a published PR branch by merging the default branch into it, never by rewriting it: a review status belongs to one exact head, and git's own guidance is that "rebasing (or any other form of rewriting) a branch that others have based work on is a bad idea" (git/git@v2.56.0 `a018953688f1b10bddf91bff8747068f5f4746a4`:`Documentation/git-rebase.adoc:1019-1020`). A local branch that was never pushed may be rebased. Evidence: PRs #49 and #66 each took `main` by a merge commit, and their earlier reviewed heads stay readable.
- The review window counts the diff's context lines too (`scripts/pr-check.sh:44-45`, `git diff origin/main...HEAD | wc -c`). A manifest or landscape row is 700 to 1,700 characters, so a one-row change measures thousands of characters more or less depending on its neighbours. Measure early, and let a landscape cell travel in its own docs PR when a part would not fit; PR #65 did, at 40,538 characters for its module, proofs and one manifest row.
- A proof named for a bound must reach the bound. PR #65's "above two hundred" batch proof sent 100 symbols until the review counted them ([#69](https://github.com/seathatflowsinourveins/sextant-movers/issues/69)); the fix asserts the size of the input the name promises, and the same input one below the bound gives the other answer.
- A closing keyword closes one issue, so each issue gets its own: GitHub Docs, [Linking a pull request to an issue using a keyword](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue), read 2026-11-11, "Multiple issues: Use full syntax for each issue". [#94](https://github.com/seathatflowsinourveins/sextant-movers/pull/94) wrote "Closes #86 and #87" and only #86 closed.
- With an allowed-actions list, the new commit of an action bump goes onto the list before the bump's `ci` can start, and the old entry comes off only after the merge: "By default, only actions and reusable workflows specified in the list will be allowed" (GitHub Docs, [Allowing select actions and reusable workflows to run](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository), read 2026-11-11). Done so for [#82](https://github.com/seathatflowsinourveins/sextant-movers/pull/82); [SETUP.md](../../SETUP.md) "Nested actions" covers what a composite action names.
- Reproduce a review finding before fixing it: write its witness, run it red on the head it names, then change the code. The note on [#92](https://github.com/seathatflowsinourveins/sextant-movers/pull/92)'s first head ([#96](https://github.com/seathatflowsinourveins/sextant-movers/issues/96)) came labelled `static: no witness run`; its four cases ran 4 failed, 37 passed before the guard changed. [LESSONS.md](../LESSONS.md) lesson 3.
- A writer whose own sandbox cannot run a check reports it as "not run here, and why" and still commits every finished step; the lead runs that check on the head before publishing. A sandbox refusal is not a failed change and never a reason to respell the command. [#92](https://github.com/seathatflowsinourveins/sextant-movers/pull/92): a read-only container without network could not run three checks, and all three ran on the published head.
- A part cut for the review window carries a manifest Proof cell that names only what its own head holds; the next part adds its own proof. `tests/repo/test_manifest_proofs.py` refuses a named test that is not in the tree ([#98](https://github.com/seathatflowsinourveins/sextant-movers/pull/98)).
